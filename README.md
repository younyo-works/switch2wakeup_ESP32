# Switch 2 Wakeup - Stand-alone 版

ESP32-C3 から BLE の起動信号を送り、スリープ中の Nintendo Switch 2 を起動する実験プロジェクトの「スタンドアローン版」です。
一度ファームウェアを書き込めば、以後は PC なしで、ボタン操作だけで Switch 2 の情報(MAC アドレスなど)を登録し直せます。

> **⚠️ 先に必ずお読みください:** このプロジェクトは完全に**個人の実験用**です。

## 概要

### 何をするものか

| 項目 | 内容 |
|---|---|
| マイコン | ESP32-C3(動作想定: ESP32-C3 Super Mini) |
| 通常時 | ディープスリープで待機 |
| ホームボタン(GPIO4) | 押すとスリープから復帰し、起動信号を送信して再びスリープ(最低3秒、押している間は最大30秒まで延長) |
| マイナスボタン(GPIO3) | 押したまま起動/ホーム押下でスキャナーモード(15秒)に入る |
| スキャナーモード | Joy-Con 2 のボタンを押した時の信号から、Joy-Con と Switch 2 本体の MAC・PID を取得して保存 |
| 初期値(ダミー) | Joy-Con: `AA:BB:CC:DD:EE:FF` / Switch 2: `11:22:33:44:55:66` |

初期値はダミーなので、**登録するまで Switch 2 は起動しません**(想定どおりの挙動です)。

### 仕組み(ざっくり)

1. Switch 2 は、ペアリング済みのコントローラーが出す BLE の起動パケットを受けるとスリープから復帰します。
2. このデバイスは、登録した Joy-Con の MAC アドレスになりすまして、宛先を Switch 2 の MAC にした同形式のパケットを送ります。
3. スキャナーモードでは逆に、本物の Joy-Con 2 が出すパケットを受信して、必要な MAC・PID を読み取ります。

参考にしたプロジェクト: [alexvnesta/switch2controller](https://github.com/alexvnesta/switch2controller)
(ライセンスや利用条件は、参考元のリポジトリで各自確認してください)

### 2つの版の違い

送信・スキャン・設定の仕組みは共通で、ボタンの読み取り方だけが違います。作り方に合う方を選んでください。

| 版 | 向いている作り方 | ボタンの接続 |
|---|---|---|
| 組み込み版 (`standalone`) | ESP32 を Switch プロコンに組み込み、ホーム/マイナスの信号線に割り込ませる | プロコンの信号線(パルス信号を ADC で判定) |
| 単体版 (`standalone_button`) | ESP32 と物理ボタンだけで独立した起動装置を作る | GPIO と GND の間にタクトスイッチ等(内部プルアップ、抵抗不要) |

## 配線

| ESP32-C3 | 接続先 |
|---|---|
| GPIO4 | ホームボタンの信号線 |
| GPIO3 | マイナスボタンの信号線 |
| GPIO8 | 基板上の LED(Super Mini の青 LED) |

- ピン番号はスケッチ冒頭の `PIN_HOME` / `PIN_MINUS` で変更できます。ホームは GPIO0〜5、マイナスは GPIO0〜4 から選んでください(GPIO2 / 8 / 9 はブート設定ピンなので避けてください)。
- マイナスボタンは「起動のきっかけ」にはしていません。ホーム押下時または電源投入/リセット時に、押されているかどうかを見るだけです。
- **コントローラーのホーム/マイナス線は、GND へ直結される単純な接点ではありません**(実機での測定結果)。未押下で約1.8V、押した線はパルス状に 0V 付近まで落ちる信号のため、押下判定はデジタル読みではなく ADC で最小値を見ています。
- コントローラーの基板に配線する場合は、その信号線の構造と電圧を、**必ずテスター等で事前に確認してください**(マトリクス接続や、電圧の異なる回路につなぐと破損の原因になります)。

## ビルドと書き込み

### 1. バイナリを作る(Arduino IDE)

1. ボードを **ESP32C3 Dev Module** にします。
2. **USB CDC On Boot** を **Enabled** にします。
3. ライブラリ **NimBLE-Arduino 2.x** をインストールします。
4. `switch2_wakeup_standalone.ino` を開き、「スケッチ → コンパイル済みバイナリをエクスポート」を実行します。
5. 出力された **`.merged.bin`** を `switch2_wakeup_standalone.bin` に改名し、`index.html` と同じフォルダに置きます。

※ シリアルモニタを使う場合は **Arduino IDE 2.x を推奨**します。IDE 1.x のシリアルモニタは、ESP32-C3 のネイティブ USB シリアル(ディープスリープでポートが消えて復帰する動作)との組み合わせで、表示が不安定になることが確認されています。

### 2. 書き込む

**方法 A: ブラウザ(推奨)**

1. [index.html](index.html) を開きます。
2. ESP32 を USB で接続し、「ポートを選んで接続」→「書き込み開始」を押します。
3. 接続できないときは、BOOT ボタンを押したまま USB を差し直してから、もう一度試します。

**方法 B: Arduino IDE から直接書き込み**

通常の手順で書き込めます。

## 操作方法

### 書き込み直後

- 再起動後、**約5秒間** LED が1秒に1回短く光ります(この間は USB・シリアルが使えます)。
- その後ディープスリープに入ります。**スリープ中は USB の接続が切れますが、正常です。**

### Switch 2 の情報を登録する(スキャナーモード)

1. Switch 2 本体をスリープ状態にします。
2. 次のどちらかの方法でスキャナーモードに入ります。
   - **マイナスボタンを押したまま、ホームボタンを押す**
   - **マイナスボタンを押したまま、電源投入またはリセット**
3. LED が「ピピッ」と繰り返し光れば、スキャナーモードです(15秒間)。
4. 15秒以内に、ペアリング済みの **Joy-Con 2 の任意のボタンを押します**。本体から外す操作で反応するかは未検証です。
5. 受信できると LED が2秒間点灯し、保存してスリープに入ります。
6. ホームボタンを押して Switch 2 が起動すれば登録完了です。

見つからなかった場合は、LED が5回素早く点滅し、設定は変更されないままスリープに入ります。

### 通常の使い方

ホームボタンを押すと、LED が高速で点滅しながら起動信号を送信し、その後スリープに戻ります。
送信は最低3秒で、ボタンを押し続けている間は最大30秒まで延長されます。確実に起動させたい時は、Switch 2 の画面が点くまで押し続けてください。

### LED の見かた

| LED | 意味 |
|---|---|
| 1秒に1回、短く光る | 起動直後の待機中(約5秒) |
| 高速で点滅 | 起動信号の送信中 |
| 「ピピッ」を繰り返す | スキャナーモード(15秒) |
| 2秒間点灯 | 登録成功 |
| 5回素早く点滅 | 登録失敗(設定は変更なし) |

LED の点灯と消灯が逆に見える場合は、スケッチ内の `LED_ACTIVE_LOW` を `false` にしてください。

### シリアルコマンド(リセット後5秒の間だけ有効)

115200bps、改行コード LF で送ります。

| コマンド | 内容 |
|---|---|
| `SHOW` | 現在の登録内容を表示 |
| `CLR` | 登録内容を消して初期値(ダミー)に戻す |
| `CFG:<JoyCon MAC>,<Switch MAC>,<PID>` | 手動で登録(例: `CFG:AA:BB:CC:DD:EE:FF,11:22:33:44:55:66,0x2066`) |

- PID は右 Joy-Con 2 が `0x2066`、左 Joy-Con 2 が `0x2067` です。
- 待機中の画面には、現在の登録内容に加えて、前回の送信/スキャンの結果(`Last event:`)も表示されます。送信を取りこぼした疑いがある時は、リセットしてこの表示を確認してください。
- ディープスリープに入るとシリアルモニタは切断されます。再度使う時は、リセット後にモニタを開き直してください。

## 調整できる値(スケッチ冒頭)

| 定数 | 初期値 | 内容 |
|---|---|---|
| `BURST_MS` | 3000 | 起動信号の最低送信時間(ms)。**実績値です。短くすると起動の取りこぼしが増えるため、短くしないでください** |
| `MAX_BURST_MS` | 30000 | ホームを押し続けた場合の送信延長の上限(ms) |
| `SCAN_MODE_MS` | 15000 | スキャナーモードの時間(ms) |
| `SCAN_MIN_RSSI` | -75 | これより弱い電波は無視する(他人の Joy-Con 誤取得防止) |
| `SCAN_SETTLE_MS` | 1500 | 最初の検出後、より強い電波を待つ時間(ms) |
| `SERVICE_WINDOW_MS` | 5000 | リセット後に USB を生かしておく時間(ms) |
| `WAIT_RELEASE_BEFORE_SLEEP` | true | ボタンを離すまでスリープしない |

## トラブルシューティング

| 症状 | 確認すること |
|---|---|
| ブラウザで接続できない | BOOT ボタンを押したまま USB を差し直す。別の USB ケーブル(データ通信対応)を試す |
| ページが動かない | `file://` ではなく localhost / https で開いているか。Chrome / Edge か |
| 書き込み後に PC からデバイスが消えた | スリープに入ると USB が切れるのは正常。BOOT を押しながら差し直す |
| スキャナーモードで見つからない | Joy-Con 2 を ESP32 に近づける。Joy-Con 2 のボタンを押すタイミングを15秒以内にする。Switch 2 をスリープさせておく |
| 登録したのに Switch 2 が起動しない | 登録後に Switch 2 側で Joy-Con 2 の登録を解除していないか。登録し直して再スキャン |
| 起動したりしなかったりする | 画面が点くまでホームを押し続けてみる(押し続けている間は送信が延長されます)。`BURST_MS` が 3000 になっているか確認する。`SHOW` で登録内容がダミー値のままになっていないか確認する。ESP32 を Switch 2 に近づける |
| シリアルが表示されない | Arduino IDE 2.x のシリアルモニタを使う。リセット後にモニタを開き直す。スリープ中は表示されないのが正常 |
| LED の点灯が逆 | `LED_ACTIVE_LOW` を切り替える |
| ファームを更新したら登録が消えた | 結合 bin の書き込みで保存領域も初期化されるため。再度スキャナーモードで登録する |

## 既知の制限

- **実機での検証が十分ではありません。** 動作しない環境や、動作が変わる環境があり得ます。
- Joy-Con 2 を**本体から外す操作**で信号が出るかは未検証です。確実なのは、本体スリープ中に Joy-Con 2 のボタンを押す方法です。
- Switch 2 のシステムソフトウェア更新により、予告なく動作しなくなる可能性があります。
- 近くに他人の Joy-Con 2 があると、誤って取得する可能性があります(RSSI の閾値で軽減していますが、完全ではありません)。
- スリープ中も、基板の LED やレギュレーターで電流が流れます。電池駆動で長期間使う場合は、基板側の対策が必要です。
